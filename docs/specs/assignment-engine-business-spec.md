# Assignment Engine Business Spec

> Design notes for this feature came from a clean-room reading of an external reference system licensed AGPL-3.0 (see `docs/research/learnhouse/`) — this spec describes independently designed mentingo behavior, not ported code. Status: **beta** (still marked Beta in `SelectLessonType`), but feature-complete for the golden path as of the 2026-07-25 completion pass — see "Test Evidence" and "Follow-up Work" for exactly what is and isn't covered.

## Business Overview

The Assignment lesson type lets course creators set graded homework inside a course: a short-answer question judged by AI, a numeric exercise, a chess position line played on a real board, a PGN analysis with board context, or a file upload. Learners answer each task, get graded automatically where possible, and see their overall result once every task in the assignment has a grade. Trainers grade ungraded/manual tasks from a dedicated grading page.

This closes the largest gap identified when comparing mentingo against LearnHouse (see `docs/research/learnhouse/03-feature-matrix.md`): mentingo had no assignment/submission concept at all before this feature — quizzes cover fixed-answer questions, but nothing captured free-form or multi-step graded work.

## Who Uses It

- Course creators / trainers add an assignment lesson to a chapter, defining its grading rules and tasks.
- Learners open the lesson, answer each task, and see feedback and their grade once graded.
- Trainers with grading permission review ungraded submissions (chiefly file submissions and AI-graded free text they want to double-check) and can override any task's grade.

## Feature Functions

- Create an assignment lesson with a title, optional description, due date, and grading configuration: grading type (numeric/percentage/pass-fail/letter/GPA), whether correct answers are shown to learners once graded, whether retries are allowed and how many, and a pass threshold.
- Edit an existing assignment lesson's title/description/settings and add, edit, or remove tasks — the authoring form loads the existing assignment back in and diffs tasks on save (add/update/delete) rather than being create-only.
- Delete an assignment lesson through the same generic curriculum-editor delete flow every other lesson type uses (the `assignments`/`assignment_tasks`/submissions rows cascade-delete via the `lessons` FK).
- Add tasks of five types: short answer (AI-graded), number answer (exact match with tolerance), chess position line (play the winning line on a real board; UCI move sequence, exact match), chess PGN analysis (AI-graded, with an optional starting-position board for context), file submission (manual grading only, with allowed-extensions and max-size configuration).
- Learners submit an answer per task on a UI matched to the task type — a real interactive chess board for position-line tasks, a board-plus-textarea for PGN analysis, a file picker with upload for file submissions. Eligible types are graded immediately (deterministic graders for number/chess-line, an AI judge for short-answer/PGN-analysis).
- The learner's overall grade is the percentage of achieved points across every task in the assignment, recomputed whenever a task submission or its grade changes.
- Once every task has a grade, the assignment's status becomes `graded` and — only if `showCorrectAnswers` is enabled — the learner can see each task's reference answer.
- A trainer grades manually-graded and AI-graded submissions from a dedicated grading page (`/admin/assignments/:lessonId/grading`): a list of learners with status/grade, and a detail view per learner showing each task's submitted content (including a downloadable link for file submissions) with grade and feedback inputs. A manual grade always overrides auto/AI grading for that submission until the learner resubmits.
- Retries: if the assignment forbids retries, a learner cannot resubmit after being graded; if it allows a limited number, resubmission is blocked once the limit is reached.
- If a trainer re-grades a task and the learner's overall result drops below the course's pass threshold, any certificate already issued for that course is automatically archived (not deleted — the learner's progress/lesson completion is untouched, only the certificate is revoked).

## End-User Value

For a chess school, this is the first way to assign real homework inside mentingo: "analyze this PGN and explain what went wrong," "solve this endgame in the fewest moves on the board," "upload your tournament game score sheet." Trainers get a single place to define graded work, grade what needs a human, and see results, instead of grading outside the platform — and a certificate issued on a since-corrected grade doesn't stay valid by accident.

## How It Works

A trainer picks "Assignment" from the lesson-type picker (marked Beta), sets the title, grading options, and adds one or more tasks with type-specific fields (a reference answer for short answer, an expected number and tolerance for number answer, a starting FEN plus a played-out winning line on an interactive board for chess position line, an optional FEN for PGN analysis context, allowed extensions/max size for file submission). Saving creates the lesson and its assignment definition together in one call, after the same course-content-lock, curriculum-editing-feature-flag, and per-course ownership checks every other lesson type's create path runs, and publishes the same `CreateLessonEvent` activity-log entry. Reopening an existing assignment lesson loads its tasks back into the form; saving diffs the task list against what's on the server (add new tasks, update changed ones, delete removed ones) rather than recreating everything.

A learner opens the lesson and sees each task with an input matched to its type: a text area for short answer, a number field, an interactive chess board (click-to-move, same board component the chess quiz questions use) for position-line tasks, a board-plus-textarea for PGN analysis, or a file picker for file submissions (uploaded through the platform's existing generic upload endpoint). Submitting a task grades it immediately when possible; the assignment's overall status and grade update after every task submission. Answer keys are filtered out of every response to a learner until their submission is fully graded and the assignment explicitly allows showing them — enforced in one place (`AssignmentsService.stripAnswerKey`) rather than left to the UI.

A trainer with grading permission opens the grading page from the assignment's authoring form, picks a learner from the submissions list (shown with name/email, not a bare user id), and sees each task's submitted answer alongside a grade and feedback field. File submissions show a server-signed, time-limited download link rather than exposing the raw storage key. Saving a grade recomputes the learner's overall result and, if this was a re-grade that now falls below the pass threshold, archives any certificate already issued for that course.

## Key Technical Context

- Backend module: `apps/api/src/assignments/` (controller, service, repository, TypeBox schemas, `graders/` for number-answer and chess-position-line deterministic grading, and an AI grader built on `ChatService.judge` — the same OpenAI judging primitive `JudgeService` uses for AI Mentor, reused directly rather than through the thread system since a task submission is a single answer, not a conversation). The AI grader resolves the task's title/description in the course's base language via `LocalizationService.getBaseLanguage`, matching other AI-prompt call sites, rather than picking an arbitrary locale.
- Schema: `assignments`, `assignment_tasks`, `assignment_task_submissions`, `assignment_user_submissions` in `apps/api/src/storage/schema/index.ts`; migrations `0166_lean_nick_fury.sql` (tables) and `0167_enable_assignment_tenant_rls.sql` (RLS — applied and verified against the local dev database).
- Shared constants: `packages/shared/src/constants/assignments.ts` (grading types, task types, submission statuses); lesson type added to `packages/shared/src/constants/lessonTypes.ts`; `CERTIFICATE_ARCHIVE_REASONS.ASSIGNMENT_REGRADE` added to `packages/shared/src/constants/certificate.ts`.
- Permissions: `assignment.read`, `assignment.manage`, `assignment.manage_own`, `assignment.grade`, `assignment.submit` in `packages/shared/src/constants/permissions.ts`, mapped into all four system roles.
- Lesson-system parity: `AssignmentsService` injects `AdminLessonService`, `MasterCourseService`, and `CourseFeaturePolicyService` (via `AssignmentsModule` importing `CourseModule` with `forwardRef`) to run `assertCourseContentEditableBy{ChapterId,LessonId}`, `assertCourseFeatureEnabledBy{ChapterId,LessonId}(..., COURSE_FEATURE.CURRICULUM_EDITING)`, and `validateAccess` (the `*_MANAGE_OWN` per-course-authorship check) on every authoring mutation (create lesson, create/update/delete assignment, add/update/delete task) — previously only the coarse `@RequirePermission` decorator gated these, so a `MANAGE_OWN` user could edit any course's assignments, not just their own. `createAssignmentLesson` publishes `CreateLessonEvent` via `AdminLessonService.publishCreateLessonEvent`. Deleting an assignment lesson goes through the generic `DELETE /lesson?lessonId=` (`AdminLessonService#removeLesson`) rather than a dedicated endpoint — `assignments.lesson_id` cascades on delete, so no assignment-specific deletion logic was needed.
- Certificate revocation: `AssignmentGradedEvent` (published whenever a learner's assignment grade is (re)computed) is consumed by `AssignmentGradedCertificateHandler` (`apps/api/src/certificates/handlers/`), registered in `CertificatesModule`. It only acts on a regrade (`isRegrade: true`) that now fails (`passed: false`) — a first grading pass has no certificate to revoke yet, and a regrade that still passes needs no action. It resolves the lesson's course via a `lessons` → `chapters` join and calls `CertificatesService.archiveCertificateForFailedRequirement`, a new method that archives the active certificate for that (user, course) **without** resetting progress — unlike the admin-triggered `resetCourseCertificates` flow, which deliberately also resets lesson/course progress for a "let them retake everything" reset.
- Grading: `GET /assignments/:id/submissions` now joins `users` for name/email (`AssignmentUserSubmissionWithUserRecord`/`assignmentUserSubmissionWithUserSchema`) so the grading UI shows who it's grading, not a bare userId. `GET /assignments/:id/submissions/:userId` resolves a signed download URL for any task submission with a `fileS3Key` via `FileService.getFileUrl` (added to `AssignmentsModule`'s imports), so a trainer can actually open a submitted file rather than seeing an opaque storage key.
- Frontend API client: fully migrated onto the generated swagger client (`pnpm generate:client`, `ApiClient.api.assignmentsController*`) — the previous hand-rolled `apps/web/app/api/assignments-api.ts` has been deleted. One hook per file under `apps/web/app/api/{queries,mutations}/[admin/]use*.ts`.
- Frontend authoring: `apps/web/app/modules/Admin/EditCourse/CourseLessons/NewLesson/AssignmentLessonForm/AssignmentLessonForm.tsx` — `courseLessonContentType.utils.ts` now maps `LessonType.ASSIGNMENT` to `ContentTypes.ASSIGNMENT_FORM`, so clicking an existing assignment lesson opens this form (previously fell through to a blank pane). The form loads `useAssignmentForAuthor(lessonId)` when editing, diffs tasks against the server on save, and has a delete button wired through the generic `useDeleteLesson` hook plus `DeleteConfirmationModal`.
- Frontend learner view: `apps/web/app/modules/Courses/Lesson/AssignmentLesson/AssignmentLesson.tsx`, wired into `LessonContentRenderer.tsx`. Chess position-line tasks use `AssignmentChessMoveInput` (a controlled wrapper around `ChessBoard`, same pattern as the quiz module's `ChessMoveQuestion.tsx`); PGN analysis tasks show `FenBoard` for context alongside the textarea; file submissions upload through `useUploadFile` (the same generic upload hook other authoring flows use) and store the returned S3 key.
- Frontend grading: `apps/web/app/modules/Admin/AssignmentGrading/AssignmentGrading.page.tsx`, routed at `admin/assignments/:lessonId/grading` (`apps/web/routes.ts`, gated in `routeAccessConfig.ts` by `ASSIGNMENT_GRADE`), linked from the authoring form when editing an existing assignment lesson.
- i18n: 25 new UI strings across all 7 locale files (en/vi/pl/de/es/lt/cs) with real (not machine-copied) translations — task-type labels in the authoring dropdown, chess/file-submission field labels, and the full grading page.

## Test Evidence

Backend: 18 Jest unit tests — the original 12 (`number-answer.grader.spec.ts`, `chess-position-line.grader.spec.ts`, and 7 in `assignments.service.spec.ts` covering answer-key stripping, the retry gate, and auto-grading) plus 2 new tests in `assignments.service.spec.ts` (lesson-creation runs the content-lock/feature-flag/ownership checks and publishes `CreateLessonEvent`; propagates the content-lock error instead of creating the lesson) and 4 new tests in `assignment-graded-certificate.handler.spec.ts` (archives on a failing regrade; no-ops on a first grading pass, on a regrade that still passes, and when the lesson can't be resolved to a course). Full `pnpm run test:api` (282/282) and the certificates E2E suite (32/32, re-verified after the grading/revocation changes) pass with no regressions. `tsc --noEmit` and `eslint` are clean on the whole API package.

Frontend: `tsc --noEmit` and `eslint` are clean on the whole web package; full `pnpm run test:web` (202/202) passes with no regressions.

## Follow-up Work (explicitly not done in this pass)

- **E2E coverage**: no Playwright specs yet for the assignment flows, unlike the chess module's `apps/web/e2e/{data,factories,flows,specs}/chess/` pattern. Everything above was verified via unit tests, the full test suites, and manual code-path review — not browser-driven end-to-end tests.
- **Grading page polish**: the grading page is functional but minimal (no pagination for large submission lists, no bulk actions, no filter by status). Fine for a chess school's expected volume; would need work at larger scale.
- **Due-date handling**: `dueDate` is stored and read but nothing currently notifies a learner about an approaching deadline or blocks late submission beyond marking the status `late` after the fact — no reminder email, unlike `CourseDueDateReminder` for other content.
